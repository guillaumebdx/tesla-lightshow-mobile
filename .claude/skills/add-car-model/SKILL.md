# Add a car model (or a new GLB)

The Model Y Juniper (April 2026, ~2700 lines across 31 files) is the reference implementation. To see every place a car model touches, run `git diff --stat 0e2ad25 dc21a6a -- . ':!*.glb'`.

## Reference material

- `reference/glb-pipeline.md` — Blender export -> `_geo.glb` (textures stripped), React Native constraints (no embedded textures, no Draco/meshopt, no WebP).
- `reference/glb-model-guide.md` — node naming, the node-name remapping table, materials, animation axes (written for the Model 3 GLB).
- `reference/freelancer-brief-juniper.md` — the brief sent to the 3D freelancer for the Juniper. Copy it as the template for the next model.

## Steps

1. **GLB**
   - Put the source in `assets/models/`, then point `scripts/glb/inspect_model.mjs` at it and run `node scripts/glb/inspect_model.mjs`. It prints the node tree and writes the `_geo.glb`.
   - `scripts/glb/inspect_scene.mjs`, `inspect_trunk.mjs` and `inspect_flap.mjs` print the node transforms and parent chain. Use them before animating any closure: local axes are often not world axes (the Juniper meshes carry a +90° Y rotation on the node).
   - "Selectable but doesn't light up" usually means flipped normals. Use `side: THREE.DoubleSide` on that material.
2. **Register the car** in `src/carModels.js`: `glb` (static `require`, Metro needs it), `channelCount` (48, or 200 if the car has light bars or RGB), `modelScale`, `modelLift`, and feature flags (`juniperExtensions`).
3. **Picker**: set `available: true` in the local `CAR_MODELS` array of `src/NewShowScreen.js`. It is a different list from `CAR_MODELS` in `carModels.js`. Unavailable cars show the vote CTA.
4. **Model-specific parts**: if the car has parts other cars don't have, add a set like `JUNIPER_ONLY_PARTS` in `src/constants.js`. `ModelViewer.js` filters by it when loading. Wire each new part with the `add-vehicle-part` skill.
5. **Export**: confirm the channel layout with the `fseq-export` skill. Write a reference doc for the car's channels like `juniper-200-channels.md`.
6. **AI generation**: today the backend only knows `model_3` and `model_y_juniper` (`backend/src/routes/generateShow.js` coerces anything else to `model_3`). Add the model there, in `getPatternCatalog` / `expandChoreography` (`patterns.js`) and in the prompt addendum (`llmService.js`). See the `ai-show-generation` skill.
7. **Votes**: once the car is available, decide whether to keep it in `VALID_MODELS` in `backend/src/routes/votes.js`. Old app versions still send votes for it, so keep it accepted server-side.
8. **Demos**: add per-car demo variants in `src/demoShows/index.js` (`getDemoForCar`).
9. **Text**: car name and any new strings in all 4 locales, then `node scripts/check-i18n.mjs`.

## Done when

The car can be picked, loaded, edited, exported to a valid FSEQ with the right channel count, generated by the AI, and played in the demo viewer, with no Juniper-only or new-car-only part showing up on other cars.
